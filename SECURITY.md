# Security reporting

## Report privately

Please never disclose secrets, credentials, or exploit instructions in public issues, pull requests, or discussion. If GitHub private vulnerability reporting is available in this repository, use it. That channel may be unavailable; if so, use the maintainer profile to request private contact instructions and do not send details until the maintainer confirms a contact route.

## Safe report contents

Provide only sanitized information: affected path or version, impact summary, minimal reproduction steps, and a non-sensitive fixture. Do not include tenant or subscription identifiers, corporate registry identities, internal test reports, tokens, or production data.

This project is a proof of concept. A proof-of-concept reproduction is not production authorization. Do not run automatic cloud commands while reproducing an issue. State whether the issue involves a new APIM service or an optionally reused existing Foundry deployment, and note any recovery step that preserves service or data.
